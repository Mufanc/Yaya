Examples:
  yaya attach --port 8701
  yaya thread list --session s_k7m2px
  YAYA_SESSION=s_k7m2px yaya class find 'com/example'
  yaya events --session s_k7m2px --wait 30s
  yaya ui windows --session s_k7m2px
  yaya ddm features --session s_k7m2px
  yaya attach --port 8701 --interactive

Connection: prepare a JDWP TCP endpoint yourself, e.g. with adb forward tcp:8701 jdwp:PID. yaya does not start apps, enable debugging, or interpret obfuscation mappings. Session: use the ID returned by attach. -s/--session goes after the top-level command (e.g. yaya thread list -s ID); it overrides YAYA_SESSION. Within command groups it may appear before or after the leaf command. attach and sessions do not accept it; no automatic selection. Output: command results, events and execution errors are JSONL. Help/version and parsing errors use clap's plain text. Exit codes: success 0, execution error 1, CLI usage error 2. Runtime object/type/thread/frame IDs and DEX PCs accept decimal or 0x-prefixed hexadecimal; break remove takes a decimal event_request_id. Runtime IDs belong to one connection. Run 'yaya <command> --help' or 'yaya <group> <command> --help' for details.
Android DDM: ui windows enumerates ViewRoots, ui dump decodes a fresh V2 hierarchy, and ui capture redraws an explicitly selected View into a client-local PNG. Window names and View selectors are not JDWP object IDs. No View cache or automatic resume is used. ddm features queries advertised capabilities; ddm raw sends a four-character chunk with an optional hex payload.
Primitive inspection: string get reads string contents; array length/get/set exposes array operations; frame this returns the receiver; object referrers queries direct references. thread suspend and vm suspend explicitly pause their respective targets; thread suspend-count queries the VM without local state tracking.
