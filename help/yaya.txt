Examples:
  yaya attach --port 8701
  yaya threads --session s_k7m2px
  YAYA_SESSION=s_k7m2px yaya class find 'com/example'
  yaya events --session s_k7m2px --wait 30s
  yaya attach --port 8701 --interactive

Connection: prepare a JDWP TCP endpoint yourself, e.g. with adb forward tcp:8701 jdwp:PID. yaya does not start apps, enable debugging, or interpret obfuscation mappings. Session: use the ID returned by attach. -s/--session goes after the top-level command (e.g. yaya threads -s ID); it overrides YAYA_SESSION. Within command groups it may appear before or after the leaf command. attach and sessions do not accept it; no automatic selection. Output: command results, events and execution errors are JSONL. Help/version and parsing errors use clap's plain text. Exit codes: success 0, execution error 1, CLI usage error 2. Runtime object/type/thread/frame IDs and DEX PCs accept decimal or 0x-prefixed hexadecimal; break remove takes a decimal event_request_id. Runtime IDs belong to one connection. Run 'yaya <command> --help' or 'yaya <group> <command> --help' for details.
